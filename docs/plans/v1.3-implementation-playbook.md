# Hyperloop v1.3 — Implementation Playbook

**Source of truth:** `HYPERLOOP_CODEX_HANDOFF.md` (v1.3; numbered copies removed). Section 0 overrides older ambiguous sections; v1.2 (Section 15, SDD-only planning) and M1.5 (100-slot admission) remain in force.
**Repo layout:** monorepo `hyperloop-cloud`; each `hyperloop-*` folder keeps the component ownership from Section 0.1.
**Baseline (2026-10-27):** M0–M4 + v1.2 SDD gates implemented and green (`contracts` 21, `control-plane` 46, `agent-runtime` 12, `integrations` 9, `teams-gateway` 4 tests). Adapters are in-memory; Kiro CLI not invoked.

Run phases in order. Each phase ends with a **gate**: commands that must pass before the next phase starts. Every phase is one PR.

## P1 — Remove in-process agent execution from Control Plane

**Problem:** `control-plane/src/application/planner-vertical-slice.ts` and `coding-vertical-slice.ts` import `runPlanner` / `runCoding` from `@hyperloop/agent-runtime` and execute them inside the Control Plane process. v1.3 forbids this.

**Tasks**
1. Control Plane side becomes *job-result driven*:
   - Add `src/application/agent-result-ingestor.ts`: reads the agent result manifest (S3 URI from Job labels/annotations or result callback), validates against `agent-result.schema.json`, then calls `orchestrator.completePlanner(...)` or `orchestrator.recordCodingResult(...)`.
   - Scheduler `finalizeFromKubernetes(taskId)` → on `Succeeded`, hand the task to the ingestor; on `Failed`, record failure. Slot release-once stays as is.
2. Delete `planner-vertical-slice.ts` and `coding-vertical-slice.ts` from `control-plane/src/application/`.
3. Move their end-to-end tests to a new workspace-level harness `e2e/` (outside every service package) that wires Control Plane + a fake Kubernetes adapter which, on `createJob`, runs the agent-runtime entrypoint in a child process and writes the result manifest to the in-memory/S3 artifact store.
4. Remove `"@hyperloop/agent-runtime"` from `control-plane/package.json`; regenerate lockfile.
5. Replace hard-coded `agentImage: 'nexus.example/hyperloop/kiro-agent:0.1.0'` with config `AGENT_IMAGE_PLANNER|CODING|FIX` (digest allowed) + image allowlist check in `job-builder.ts`.

**Gate**
```bash
rg -n "agent-runtime|invokeKiro|\bkiro\b" hyperloop-control-plane/src hyperloop-integrations/src   # zero non-config hits
(cd hyperloop-control-plane && npm run lint && npm test)
(cd e2e && npm test)   # planner + coding slices still pass via Job boundary
```

## P2 — AgentExecutionContract v2

**Tasks**
1. `contracts/schemas/agent-job-request.schema.json` → add required: `executionId`, `role` (replaces `stage`, keep `stage` as deprecated alias for one version), `sddRepository`, `sddCommitSha`, `devSpecPath`, `artifactPrefixUri`, `fenceToken`, `leaseExpiresAt`. Role-conditional (`if/then`):
   - planner: no `repository`, no `branchContract`, `approvedSpecHash` absent.
   - coding: `repository`, `branchContract`, `approvedSpecHash`, `approvedPlanUri`, `expectedBaseSha`.
   - fix: coding fields + `failedCommitSha`, `ciReportUri`, `fixAttempt` ∈ {1,2}.
2. Bump `contracts/versioning.md`; add valid + invalid fixtures per role.
3. Control Plane: `ExecutionFenceService` persisted in the workflow repository (not the in-memory Set in `SddRevisionManager`). Issue token per execution; revoke on SDD supersession / cancel. Expose `POST /executions/:id/authorize-push` (returns 409 when fenced or token stale).
4. Agent-runtime: `assertPushAllowed` calls `authorize-push` immediately before `git push`; on 409 → exit `HL_CODING_EXECUTION_FENCED`, no push. Verify `expectedBaseSha` before Kiro and before push.
5. Job builder passes the contract as a mounted JSON file (`/hyperloop/contract.json`) plus `HYPERLOOP_CONTRACT_URI`; no secrets in env.

**Gate**
```bash
(cd hyperloop-contracts && npm test)   # new fixtures: role mismatch, missing fenceToken, fixAttempt=3 rejected
(cd hyperloop-control-plane && npm test)   # fence revoked after new SDD SHA → authorize-push 409
(cd hyperloop-agent-runtime && npm test)   # fenced → zero commits; base SHA drift → no mutation
```

## P3 — Event Gateway

**Tasks**
1. New package path `hyperloop-integrations/services/event-gateway/` (Fastify), using adapters already in `hyperloop-integrations/src`.
   - Routes: `POST /webhooks/gitlab/sdd`, `POST /webhooks/gitlab/mr`, `POST /webhooks/jenkins/ci`, `GET /health`.
   - Auth: GitLab `X-Gitlab-Token` (constant-time compare) + optional HMAC; Jenkins shared secret/HMAC; project allowlist.
   - Normalize to `workflow-event.schema.json` types `SDD_REVISION_SUBMITTED`, `CI_RESULT_RECEIVED`, `MR_MERGED`; dedupe by delivery id (`DevSpecChangeDetector` + durable idempotency key); publish to SQS `devspec-events` (or outbox on publish failure → 503 so GitLab retries).

2. Control Plane: remove `/webhooks/*` routes from `api/app.ts`; add an SQS consumer `src/workers/event-consumer.ts` that feeds `PlanningCoordinator.intake` → `orchestrator.submitDevSpec` (with `clarificationIssues`), CI results, MR merged.
3. Add `asyncapi/events.yaml` channels for the three normalized events.

**Gate**
```bash

rg -n "webhooks/" hyperloop-control-plane/src   # zero route definitions
(cd e2e && npm test)   # gateway → queue → control-plane → planner Job desired
```

## P6 — Helm / Kubernetes

**Tasks**
1. Charts: `event-gateway`, `control-plane` (two Deployments `control-plane-api`, `control-plane-scheduler` from one image, `args: [api]` / `[scheduler]`), `teams-gateway` — all `replicas: 2`, PDB, probes, `hyperloop-system` namespace.
2. `agent-job` chart → no Deployment; ConfigMap of role → image digest allowlist consumed by the scheduler.
3. RBAC: only `control-plane-scheduler` ServiceAccount may `create/get/list/watch/delete` `batch/jobs` in `hyperloop-agents`. Agent SAs have no Kubernetes API permissions.
4. Pod Identity/IRSA per SA (scheduler: DynamoDB+SQS; planner: S3 write + SDD read; coding/fix: S3 + scoped Git).
5. NetworkPolicy: agents egress only to GitLab, Nexus, S3/STS endpoints, Kiro service endpoint; deny Kubernetes API.
6. Terraform: SQS `devspec-events`, `planner-ready`, `coding-ready`, `fix-ready` + DLQs; DynamoDB GSIs for queued intents; Karpenter agent NodePool taints.

**Gate**

|---|---|---|
| `WorkflowRepository` | DynamoDB conditional writes (exists in part) | DynamoDB Local |

## P8 — M5 Jenkins + MR merged

**Tasks**
1. Event Gateway parses Jenkins callback (`ci-result.schema.json`): repo, MR IID, pipeline id, **tested commit SHA**, gate failures, report URI.
2. Control Plane `CiDecisionService`: correlate `(workflowId, repository, mrIid, commitSha)`; stale SHA or duplicate pipeline id → no-op; pass → `READY_FOR_REVIEW` + Teams notify; fail + fixable + attempts < 2 → enqueue Fix intent; else `NEEDS_HUMAN`.
3. MR merged event → service `MERGED`; workflow `COMPLETED` only when all required services merged.

**Gate:** tests for stale callback, duplicate callback (zero extra Fix intents), pass path, exhaustion path, partial merge vs all merged.
